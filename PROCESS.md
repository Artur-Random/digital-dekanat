# Описание процесса

Журнал разработки прототипа «Кабинет, который предупреждает заранее». После каждой завершённой задачи добавляется запись по шаблону ниже. Промпты Кирилла дословно: [docs/process/prompts.md](docs/process/prompts.md). Скриншоты: [docs/process/screenshots/](docs/process/screenshots/).

## Шаблон записи

```
## ДД.ММ.ГГГГ ЧЧ:ММ МСК. Задача N: название
- Задача: одна строка.
- Что сделано: по пунктам.
- Что пошло не так и как исправлено: по пунктам или «ничего».
- Проверки: какие команды запущены и с каким результатом.
- Субагенты: кто вызван и что нашёл.
- Коммит: хэш и сообщение.
```

## Подготовка: чат-консультант в claude.ai, 10–11 ноября

Роль: второй чат Claude, где Кирилл разбирал условия конкурса, готовил инструменты и инфраструктуру. Архитектурные решения принимались в чате архитектора.

### 10.11. Условия конкурса

- Регламент: участвуют студенты любых вузов России, ограничений по гражданству нет; конкурс полностью заочный; исключительные права на всё отправленное переходят МГИМО (п. 6.2–6.4). Отсюда правило: код из других проектов Кирилла не используем.
- Повышенная стипендия МГПУ: призовое место не засчитают (Положение 33общ, п. 4.12.2: заочные мероприятия вне перечня Минпросвещения не учитываются). Участвуем ради призов и портфолио.
- Приоритет номинации «Вайб-кодинг».

### 10.11. Инструменты и процесс

- Схема в два уровня: архитектор (Claude в проекте claude.ai) проектирует и пишет задания, Claude Code исполняет, Кирилл проверяет и принимает решения.
- Репозиторий: GitHub, приватный до отправки, .gitignore для Node, без лицензии (открытая лицензия противоречит передаче исключительных прав МГИМО).
- Автоматизация журнала: хук дословной записи промптов, правило PROCESS.md в CLAUDE.md, автоскриншоты Playwright, «Запись для журнала» в конце каждой сессии чата.
- Ключевой промпт (Кирилл): «А можно как-то автоматизировать и добавление всего в PROCESS.md, чтоб я руками не переписывал?»

### 10.11. Материалы для архитектора

- Скриншоты старого и нового ЛК МГПУ: вывод «каталог ссылок без данных о студенте», экран «Настроить интересы» без видимого результата. Вошло во вводный промпт архитектору.
- Нормативка: консультант предлагал убрать документы СПО и аспирантуры, Кирилл оставил их ради универсальности. Решение: уровень образования в модели данных, правила по уровням в инструкции проекта, MVP для бакалавриата.
- Ошибки ИИ:
  - Консультант назвал действующими приказы 545общ, 762общ и 961общ. При проверке загруженных файлов выяснилось, что с 01.09.2026 их заменили 426общ и 427общ. Исправлено до старта архитектора.
  - Консультант вписал в инструкцию проекта фамилию Максима без подтверждения от Кирилла.

### 10–11.11. Хостинг

- Ошибки ИИ:
  - Консультант рассчитывал на стартовый грант Yandex Cloud. В Billing оказалось, что грант уже использован.
  - Консультант советовал пополнить баланс заранее, затем поправился: деньги списываются только за созданные ресурсы.
  - Консультант утверждал, что Claude Code сам подключится к серверу по SSH. Для облачной сессии это, скорее всего, невозможно, поэтому деплой идёт через GitHub Actions.
- Проверена оферта Timeweb: при нулевом балансе договор расторгается, данные удаляются без предупреждения (п. 10.5–10.6). Поэтому баланс положен с запасом до 3 декабря.
- Правило безопасности: пароль root не вставлять ни в один промпт, потому что хук пишет промпты в репозиторий. IP-адрес секретом не считается.

### 11.11. Личная почта в коммитах

- Claude Code нашёл личную почту в 8 коммитах. Кирилл включил приватную почту в GitHub, история переписана.
- Консультант предложил переезд в новый репозиторий из-за старых коммитов в refs/pull. Кирилл остановил: «Стоп. В чем проблема?» После объяснения риска (виден только адрес почты) решили оставить как есть. Пример, где человек остановил избыточное решение ИИ.

### 10.11. Этап 1. Концепция

- Что обсуждали: три концепции, разные по сути: А «Что от меня нужно» (кабинет-диспетчер), Б «Прозрачный деканат» (заявления как отслеживание посылки), В «Моя траектория» (стипендия, копилка достижений). Оценили четыре фишки Кирилла по ценности и цене за 12 дней.
- Решение: основа А; заявки из Б с минимальным кабинетом сотрудника; копилка из В последней и урезанно. Рабочее название «Кабинет, который предупреждает заранее».
- Почему: А закрывает главную боль (студент узнаёт о сроках и последствиях постфактум) и опирается на конкретные пункты положений; Б удваивает объём работы; калькулятор В требует оцифровать около 30 страниц таблиц Приложения 2.
- Добавлено к фишкам: кнопка «Не смогу прийти на экзамен», переносы «было → стало», ИИ в создании контента вместо ИИ в работе сайта.
- Ключевой промпт (Кирилл): «Предложи 2–3 концепции кабинета, которые отличаются по сути, а не по оформлению. Для каждой: главная проблема студента, которую она решает; принцип главной страницы; одна сильная, смелая функция; риск для реализации за 12 дней.»
- Отклонили: чат-бот по положениям в работе сайта (риск галлюцинаций, ключи ИИ на сервере); персонализацию по тегам интересов (берём реальные данные студента: курс, уровень, сроки, статусы); СПО как уровень второго тестового студента (нужен отдельный набор правил).

### 11.11. Хостинг и подготовка задания 3

- Что обсуждали: смена хостинга, деплой без SSH из облачной сессии Claude Code.
- Решение: Timeweb Cloud (Москва, 1 vCPU / 2 ГБ / 30 ГБ, Ubuntu 24.04) вместо Yandex Cloud (стартовый грант уже использован).
- Как устроено: образы собираются в GitHub Actions и передаются на сервер через docker save и scp, без реестров, потому что из России Docker Hub бывает недоступен. Docker ставится из репозитория Ubuntu. HTTPS делает Caddy: без HTTPS cookie с флагом Secure не сохраняется и вход не работает. Сброс в 04:00 запускает systemd-таймер. Мониторинг через uptime.yml.
- Подготовка сервера: Кирилл один раз вставляет в консоль скрипт bootstrap.sh. Скрипт только из ASCII-символов, потому что веб-консоль может портить кириллицу при вставке.
- Ограничение для проверок на сайте: тесты блокировки входа запрещено гонять на развёрнутом сайте, иначе они заблокируют демо-аккаунты экспертов.
- Отклонили: сборку на сервере (2 ГБ RAM мало); сторонние ssh-actions (риск цепочки поставки в публичном репозитории); отключение проверки ключа хоста при SSH; CSP с nonce в этом задании (перенесено на 18–19.11).
- Открытый вопрос: домен (пока 217-149-25-144.sslip.io).
- Решено 11.11: старые коммиты в refs/pull PR #1–#3 оставляем как есть, репозиторий публикуем без переезда (см. запись 2в).
