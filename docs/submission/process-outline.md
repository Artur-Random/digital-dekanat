# Материалы для PDF «Описание процесса»

PDF сдаётся ссылкой с доступом «всем, у кого есть ссылка». Перед отправкой проверить ссылку в режиме инкогнито. Разделы идут строго в порядке формы отправки. Ниже коротко, что писать, и ссылки на материалы в репозитории.

Записи журнала указаны по заголовкам [PROCESS.md](../../PROCESS.md): «Задача N» ищется по тексту заголовка. Промпты лежат в [docs/process/prompts.md](../process/prompts.md) под датой и временем. Скриншоты лежат в [docs/process/screenshots/](../process/screenshots/), каждая папка названа `<дата_время>` задания.

Перед вставкой в PDF замазать личные данные на скриншотах текущих кабинетов МГПУ (они у Кирилла, в репозитории их нет). Демо-пароли в PDF не вставлять.

## 1. Проблема и разделы кабинета

- **Проблема.** Оба кабинета МГПУ, старый и новый, — каталоги ссылок без данных о студенте. В них нет расписания и уведомлений. О долгах, сроках и последствиях студент узнаёт постфактум, хотя положение обязывает сообщать о долгах через личный кабинет (426общ, п. 7.10). Источник: PROCESS.md, «Проектирование», «Этап 0. Анализ текущих кабинетов МГПУ».
- **Концепция.** «Кабинет, который предупреждает заранее». Из трёх концепций выбрана А «Что от меня нужно»: из Б взяты заявки, копилка достижений из В отложена. Источник: PROCESS.md, «Этап 1. Концепция»; [spec-v1.md](../spec-v1.md), раздел 0.
- **Разделы:**
  - главная с лентой «Нужно сделать»;
  - расписание с переносами «было → стало»;
  - учёба и «Что будет, если…»;
  - заявки со сроками этапов и «Не смогу прийти»;
  - уведомления;
  - «Почему так» (нормы дословно);
  - кабинет сотрудника деканата и МФЦ.

  Подробно: [spec-v1.md](../spec-v1.md), разделы 2–3; список с аккаунтами — [comment-draft.md](comment-draft.md).

- **Нормы как основа.** Реестр из 48 норм (коды N-01–N-55): каждая сверена Кириллом по первоисточнику, у каждой дословная цитата ([norms-registry.md](../norms-registry.md)). Сверка текстов правил: [rules-review.md](../process/rules-review.md).
- **Скриншоты итога:** [2026-11-19_1414/](../process/screenshots/2026-11-19_1414/):
  - `S1-home-360.png`, `S2-schedule-week-360.png`, `S3a-discipline-debt-360.png`, `S4a-application-new-360.png`, `E2-staff-application-360.png`;
  - тёмная тема — `*-dark.png`.

## 2. ИИ-инструменты

- Таблица: [tools.md](tools.md). Основные инструменты:
  - Claude в чате проекта (архитектор);
  - Claude Code (исполнитель);
  - три субагента-ревьюера;
  - хук записи промптов;
  - Codex (ревью PR);
  - ChatGPT Images и vectorizer.ai (логотип).
- **Схема работы:** Кирилл ставит задачу → архитектор пишет задание → Claude Code делает код, тесты, PR и деплой → субагенты и Codex проверяют → Кирилл и Максим проверяют результат. Источник: PROCESS.md, «Инструменты и процесс».
- **Принцип:** ИИ используется при создании контента (тексты правил, демо-данные). Во время работы сайта ИИ не вызывается, и сайт не ходит во внешние сервисы. Источник: PROCESS.md, «Этап 1. Концепция», «Отклонили».
