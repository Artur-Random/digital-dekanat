## Заморозка после отправки (Кирилл, сразу после отправки формы)

Правило организаторов: после дедлайна содержимое по ссылкам не меняется. До 28.11.2026 включительно репозиторий и сайт остаются такими, какими были в момент отправки.

1. **Заморозить деплой:** Settings → Secrets and variables → Actions → Variables → `DEPLOY_FROZEN` = `true`. Деплой по push в main пропускается с пометкой в отчёте запуска; вручную он проходит только с `force=true` (только для восстановления доступности). Для надёжности можно ещё отключить workflow: Actions → deploy → «…» → «Disable workflow».
2. **Поставить тег отправки и запретить изменения main.** Тег: GitHub → Releases → «Draft a new release» → тег `submission-2026-11-21` на текущем `main` (жюри получает ссылку на тег). Затем Settings → Rules → Rulesets → New branch ruleset: цель — ветка `main`, включить «Restrict updates» и «Restrict deletions», статус «Active». Так в main не попадёт ни push, ни слияние PR, в том числе от Claude Code.
3. **Ночной сброс не трогать.** Таймер сброса демо-данных в 04:00 МСК работает на сервере и от GitHub не зависит. Код он не меняет и возвращает сайт к исходным демо-данным.
4. **Мониторинг доступности не отключать.** Он только проверяет, что сайт открывается, и ничего не меняет.
5. **Проверить заморозку:** последний коммит в main совпадает с коммитом на момент отправки; сайт открывается; ссылки на репозиторий и PDF открываются в режиме инкогнито.

После 28.11.2026: `DEPLOY_FROZEN` = `false`, включить workflow обратно, если отключали («…» → «Enable workflow»), и выключить или удалить ruleset для `main`.
