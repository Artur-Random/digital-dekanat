## Заморозка после отправки (Кирилл, сразу после отправки формы)

Правило организаторов: после дедлайна содержимое по ссылкам не меняется. До 28.11.2026 включительно репозиторий и сайт остаются такими, какими были в момент отправки.

1. **Отключить workflow деплоя в GitHub Actions.** Репозиторий на GitHub → вкладка «Actions» → в списке слева выбрать workflow деплоя (появится в задании 3) → кнопка «…» справа вверху → «Disable workflow». Проверка: у workflow в списке появилась пометка «Disabled». Деплой и так запускается только при изменении main, но отключение страхует от ручного запуска и случайного слияния.
2. **Запретить изменения main.** Settings → Rules → Rulesets → New branch ruleset: цель — ветка `main`, включить «Restrict updates» и «Restrict deletions», статус «Active». Так в main не попадёт ни push, ни слияние PR, в том числе от Claude Code.
3. **Ночной сброс не трогать.** Таймер сброса демо-данных в 04:00 МСК работает на сервере и от GitHub не зависит. Код он не меняет и возвращает сайт к исходным демо-данным.
4. **Мониторинг доступности не отключать.** Он только проверяет, что сайт открывается, и ничего не меняет.
5. **Проверить заморозку:** последний коммит в main совпадает с коммитом на момент отправки; сайт открывается; ссылки на репозиторий и PDF открываются в режиме инкогнито.

После 28.11.2026: включить workflow обратно («…» → «Enable workflow») и выключить или удалить ruleset для `main`.
