# PWA: требования (дизайн-проход 18–19.11)

Версия 1.1, 12.11.2026. Решение Кирилла: минимальная PWA, без push-уведомлений.
Войдёт в docs/spec-v1.md через задание 4 (раздел «PWA»), реализация в дизайн-проходе.

## Цель

«На экран Домой» на iPhone и Android, своя офлайн-страница, ни одной персональной записи в кешах браузера.

## Manifest

- name: «Студкаб. Концепт кабинета студента», short_name: «Студкаб» (short_name утверждён Кириллом 12.11). Без «МГПУ» в названии и на иконке: на домашнем экране нет адресной строки, и иконка с названием вуза выглядела бы как официальное приложение.
- display: standalone; start_url и scope: «/»; lang: ru; theme_color и background_color из токенов дизайна.
- Иконки из нашего SVG-логотипа, PNG генерируются скриптом и коммитятся: 192, 512, maskable 512 (содержимое в безопасной зоне 80%), apple-touch-icon 180. iOS не берёт иконки из manifest, поэтому apple-touch-icon обязателен.
- Мета-теги для iOS: статус-бар, заголовок приложения.

## Service worker (/sw.js, вручную, без библиотек)

- Precache: офлайн-страница, иконки, шрифт.
- Cache-first только для неизменяемой статики: /_next/static/*, шрифты, иконки.
- Навигация: только сеть; при ошибке сети показывается офлайн-страница. HTML не кешируется никогда.
- Не перехватывать: не-GET-запросы, запросы RSC (заголовок RSC или параметр _rsc), /api/*, Server Actions.
- Имя кеша содержит версию сборки, старые кеши удаляются при activate.
- sw.js отдаётся с Cache-Control: no-cache, scope «/».
- Аварийный выключатель: в docs/deploy.md описано, как заменить sw.js версией, которая удаляет себя и все кеши.

## Выход

- Ответ на выход: заголовок Clear-Site-Data: "cache" (там, где браузер его поддерживает).
- На клиенте: сообщение service worker'у удалить все runtime-кеши, затем жёсткий переход location.replace("/login"), чтобы сбросить клиентский кеш роутера.
- Все страницы за входом отдаются с Cache-Control: no-store (делается уже в задании 3). Кнопка «Назад» после выхода не показывает данные.

## CSP

worker-src 'self'; manifest-src 'self'. Регистрация service worker из отдельного файла, не inline-скриптом (совместимо с nonce).

## Режим standalone (закладывается в вёрстку с задания 4)

- viewport-fit=cover; отступы env(safe-area-inset-*) у шапки и нижней навигации.
- На iOS в standalone нет кнопки «Назад» браузера: на вложенных экранах (S3a, S4b, S5, E2 и т.п.) своя кнопка «Назад».
- Плашка концепта видна и в standalone.
- На iOS у приложения с домашнего экрана свои cookie, отдельно от Safari: войти придётся заново. Указать в comment-draft.md.

## Проверки

- Playwright (Chromium): manifest корректен, иконки грузятся; service worker зарегистрирован; навигация без сети показывает офлайн-страницу; после цепочки «вход → профиль → выход» в caches нет HTML, RSC и /api; «Назад» после выхода приводит на /login.
- prod-smoke: /manifest.webmanifest и /sw.js отвечают 200 с правильным типом содержимого.
- Вручную (Кирилл, Максим): iPhone Safari «На экран Домой», Android Chrome «Установить приложение». Проверить иконку, название, режим standalone, отступы, вход, выход, авиарежим (офлайн-страница), повторное открытие после выхода (экран входа).
- В Lighthouse 12 категории PWA нет: установку проверяем в DevTools → Application → Manifest.

## Не делаем

Push-уведомления (нужны внешние сервисы), фоновую синхронизацию, офлайн-доступ к данным.

2. Manifest и иконки: уже работает «На экран Домой».
3. Service worker и офлайн-страница.
