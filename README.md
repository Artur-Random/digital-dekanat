# Студкаб: кабинет, который предупреждает заранее

Рабочий прототип личного кабинета студента для номинации «Вайб-кодинг» конкурса MGIMO AI Challenge 2026. Вуз-основа: МГПУ, Институт психологии и комплексной реабилитации.

> Концепт для конкурса MGIMO AI Challenge 2026. Не официальный сервис МГПУ. Все данные вымышленные.

**Сайт: https://studcab.ru** (открывается из России без VPN, демо-данные сбрасываются каждую ночь в 04:00 МСК).

**Тестовые аккаунты указаны в форме отправки.** В репозитории паролей нет.

## Что это

Текущие кабинеты студента в основном состоят из ссылок. Студент узнаёт о сроках и последствиях, когда уже поздно. Студкаб показывает, что происходит у студента и что ему нужно сделать:

- **Главная** — пары ближайшего дня с переносами «было → стало» и лента «Нужно сделать»: пересдачи, сроки, готовые справки.
- **Расписание** — «Сегодня», «Завтра», «Неделя» и выбор даты. Отмены, замены преподавателя и переносы видны прямо в расписании.
- **Учёба** — оценки и долги по этапам, стипендия. Экран «Что будет, если…»: что будет при тройке, неявке или пересдаче, со сроками и последствиями.
- **Заявки** — справки, академический отпуск, «Не смогу прийти» с датой «Сообщите до …». У каждого этапа заявки свой срок.
- **Уведомления** о переносах, пересдачах и смене статуса заявок.
- **Почему так** — каждое утверждение о правилах ссылается на пункт положения МГПУ или закона. Здесь видна дословная цитата, по нормам работает поиск.
- **Кабинет сотрудника** (деканат, учебный отдел МФЦ) — очередь заявок своего подразделения. Можно сменить статус заявки или отказать с обязательной причиной.

Работает на телефоне от 360 px и на ПК. Есть светлая и тёмная темы. Сайт можно добавить на экран «Домой» (PWA).

Подробнее: [спецификация](docs/spec-v1.md), [реестр норм](docs/norms-registry.md) (каждая норма сверена человеком по первоисточнику).

## Как устроен проект

**Стек:**

- Next.js 16 (App Router, Server Actions) + TypeScript в strict-режиме;
- PostgreSQL 18 + Prisma 7, Tailwind CSS 4;
- Vitest (unit), Playwright (e2e, доступность axe, автоскриншоты);
- Docker Compose. Production: Timeweb Cloud (Москва), Caddy (HTTPS), деплой через GitHub Actions.

**Безопасность:**

- права проверяются только на сервере, доступ к данным всегда фильтруется по владельцу;
- пароли хэшируются argon2id, сессии хранятся как SHA-256 от токена;
- число попыток входа ограничено, есть заголовки CSP;
- в рантайме нет внешних запросов и вызовов ИИ.

Подробно: [CLAUDE.md](CLAUDE.md), раздел «Безопасность», и тесты в [e2e/security/](e2e/security/).

## Запуск локально

Нужны Node.js 22 (см. `.nvmrc`) и Docker.

```bash
npm install                 # зависимости и prisma generate
cp .env.example .env        # заполнить DATABASE_URL, POSTGRES_* и DEMO_PASSWORD_* своими случайными значениями
npm run db:up               # PostgreSQL в Docker на 127.0.0.1:5432
npm run db:migrate          # схема базы
npm run demo:reset          # демо-данные: логины alina, denis, mfc, dekanat, пароли — из вашего .env
npm run dev                 # http://localhost:3000
```

Проверка: http://localhost:3000/api/health отвечает `{"status":"ok","db":"ok"}`.

Перед первым `npm run test:e2e` установите браузер для Playwright: `npx playwright install chromium`.

| `npm run test`                            | Unit-тесты (Vitest)                                                              |
| `npm run test:e2e`                        | E2E-тесты (Playwright; сам поднимает dev-сервер, если `BASE_URL` не задан)       |
